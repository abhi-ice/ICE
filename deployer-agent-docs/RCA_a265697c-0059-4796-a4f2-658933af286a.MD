# RCA — SiteOps (field-ops-hub-21) deploy failure & recovery

## Summary
Full source rebuild initially FAILED at step `deploy_k8s` (run `7f87c8ff-679f-4994-8f4a-514546042d66`) with backend CrashLoopBackOff. Recovered via a manifest (`entrypoint.sh`) fix; redeploy (run `a265697c-0059-4796-a4f2-658933af286a`, image `customers-app-5`) is LIVE and healthy at https://field-ops-hub-21.emergent.host.

## Symptom
Pod CrashLoopBackOff (early), restarts=3, lastExit=1/Error. Rollout logs repeated:
```
/entrypoint.sh: line 36: emergent-env-exec: command not found
Backend failed to start at initialization, exiting
Starting FastAPI backend: emergent-env-exec /root/.venv/bin/uvicorn server:app --host 0.0.0.0 --port 8001 --workers 1  in /app/backend
```

## Root cause
The source `etc/supervisor/conf.d/supervisord.conf` (a READONLY base file, carried in via the merge of upstream ice/main) now wraps the backend command with a preview-only shim:
```
command=/etc/supervisor/emergent-env-exec /root/.venv/bin/uvicorn server:app ... --reload
```
`/etc/supervisor/emergent-env-exec` exists only in the **preview** base image. It is NOT in the production runtime image, and the Dockerfile's `COPY . /app` places source under `/app/etc/...`, never `/etc/supervisor/`. The production `entrypoint.sh` extracts the backend command from supervisord.conf and "normalizes" it by stripping the directory prefix of the first token — turning `/etc/supervisor/emergent-env-exec` into a bare `emergent-env-exec`, which is not on PATH → backend never starts → CrashLoopBackOff. Previous successful deploys had no such wrapper; the normalize step stripped `/root/.venv/bin/uvicorn` → `uvicorn` (on PATH) and worked.

## Fix applied (manifest only — Recovered)
Added one line to the `entrypoint.sh` override, mirroring the existing `--reload` strip, to remove the wrapper before normalization:
```sh
# Remove the emergent-env-exec wrapper prefix if present (preview-only; not in prod image)
COMMAND=$(echo "$COMMAND" | sed 's#[^ ]*emergent-env-exec *##g')
```
Resulting command: `uvicorn server:app --host 0.0.0.0 --port 8001 --workers 1`. Verified the transform against the real supervisord.conf in a sandbox. Full manifest set rewritten to GCS (config.yaml, entrypoint.sh, nginx.conf, Dockerfile.cloudbuild, build-frontend-artifacts.sh — only entrypoint.sh changed); resume_pipeline(force_repull=true) → succeeded.

## Note for E1 / future deploys
This is a recurring risk: if the preview `supervisord.conf` keeps the `/etc/supervisor/emergent-env-exec` wrapper, the manifest override now handles it. No source change is required, but be aware the fix lives in the per-app manifest override.
