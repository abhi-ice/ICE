Button styles — 6 options + current

Current SiteOps uses saturated emerald + saturated rose buttons everywhere. With ~30 action buttons per page (Submit, Export, +Coordination, Edit, Delete, Refresh, etc.) the screen reads loud. The patterns below are sourced from Stripe, Linear, Notion, Vercel, GitHub Primer, Apple HIG, Material 3 — each shown in light + dark with Primary / Secondary / Destructive / Ghost variants so we can compare like-for-like.

Why this works: primary = high-contrast monochrome (near-black on light, near-white on dark). Outline secondary lets the page breathe. Why this needs replacing: emerald is used for ~3-5 primary buttons per page (Submit + Coordination + New activity + + Whatever). When everything is the brand-saturated color, nothing stands out — the user's eye has nowhere to land. A tool for serious daily work needs visual hierarchy: one button shouting "do this", others quietly supporting.

Recommendation: Option A (Stripe pattern) + Option F for table row clusters

Default for the whole app: Option A — primary = monochrome (near-black light / near-white dark), secondary = outline, emerald reserved for one brand CTA per screen. This is the most "classy and sober" pattern that still gives action buttons clear visual hierarchy. It's what Stripe, GitHub, and Vercel Pro all ship.

For table row Edit/Duplicate/Delete clusters: pair with Option F — group them inside a small bordered container with icon-only buttons. Reads as a single "actions" affordance instead of three competing buttons per row.

Button → Style mapping
Submit Report → primary (mono)
+ Coordination → brand CTA (emerald) — only one per screen
+ New activity / + New project → primary (mono) (was emerald)
Export / Recompute / Refresh → secondary (outline)
Cancel / Skip → ghost
Delete (in modal) → destructive solid (rose)
Edit / Duplicate / Delete (table row) → grouped icon cluster (Option F)
