Why this needs replacing: dark sidebar in dark theme is the same color as the page (#18181b on #18181b) — no visible boundary unless you stare. In light theme it works OK but the abrupt black-on-light contrast can feel heavy. The single-color-both-themes approach saves implementation effort but loses the natural separation a proper theme-paired sidebar gives you.

Recommendation: Option A (Pure white / Deep noir)

Option A is the strongest "sober + modern + works in both themes" pick. White sidebar in light → airy, modern. Deep-noir sidebar in dark → high contrast vs the page surface so the sidebar reads as the primary navigation surface (current setup blurs into the page). Both halves use the same emerald accent for active items so the brand stays consistent.

Option C is the close runner-up if you want something even more subdued — light-grey sidebar in light, slightly-elevated zinc in dark. Stripe Dashboard pattern, very SaaS-standard.

Option D (navy in both) is worth considering if you want the brand identity to stay strong on every page — same navy rail anchors the app in both themes. Heavier but distinctive.

Skip B unless you're committing to the warm-concrete saffron palette across the whole app. Skip E unless brand-loud green sidebar is the intentional aesthetic (most users prefer neutral sidebars).

Implementation cost: ~30 minutes. Update the --v4-bg-sidebar CSS variable in index.css for each theme + adjust sidebar item text + section-title colors to match. Active-item background stays emerald-tinted. No JSX changes needed (the sidebar already reads color from the CSS var).
