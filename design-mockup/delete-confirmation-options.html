Delete confirmation — 6 SaaS patterns

Currently every destructive action on SiteOps fires window.confirm() — the native browser dialog that breaks the v4 design system, blocks the main thread, and offers no Undo. 15 files in the frontend rely on it (Vendors, DelayList, PhotoTray, Tasks, ProjectAccess, etc.). Replacing it with one of these patterns standardises the whole app. Each option below shows the SaaS app it's borrowed from in light + dark theme, with the recommendation badge at the top right.

Why this works: zero clicks to delete (click → done). The Undo button lives in the toast for ~6 seconds. This is the dominant pattern in modern productivity SaaS because it's faster than a confirm dialog AND safer — if you misclick you have a generous window to back out. Backend pattern: soft-delete with TTL — mark deleted_at = now() on click, run a hard-delete cleanup job after 24h. Undo just clears deleted_at.

Use for: manpower rows, photo tray entries, draft DRs, tasks, RFI drafts, anything where re-creating from scratch would take <30 sec. Avoid for: account deletion, project deletion, anything that cascades to many child records.

Why this fails: doesn't respect light/dark theme, has the browser's own header ("field-ops-hub-21.preview.emergentagent.com says") which looks like a phishing-ish notification, blocks the main thread, can't be styled, and offers no Undo. Power users learn to hit Enter blindly which defeats the safety purpose.

Recommendation: tiered by reversibility, not "always one pattern"

One pattern doesn't fit every destructive action. The right system uses 2-3 patterns keyed on how reversible the action is. Below is the proposed mapping for the 15 files currently using window.confirm().

Tier 1 — Cheap (Option A: Toast + Undo)
Optimistic delete + 6s undo toast. No friction.
• Manpower row delete
• Photo tray cleanup
• Draft DR delete
• Task delete (draft)
• Voice intake purge
• Copilot conversation clear
Tier 2 — Medium (Option B: Inline confirm)
Row swaps in-place. One click + one confirm.
• Vendor delete
• Project member remove
• RFI delete (open)
• Delay delete (open)
• Edit request reject
• Schedule diff dismiss
• TIA generation delete
Tier 3 — Heavy (Option F: Type-to-confirm)
Type the resource name. No accidental click.
• Project delete (cascade)
• Tenant close (already does this)
• Hard-delete submitted DR
• Bulk delete (10+ rows at once)
