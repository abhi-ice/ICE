Below are six modern SaaS treatments (Linear, Notion, Stripe, GitHub, Figma) shown in both light and dark theme, with the recommendation at the top right of each option.

Why this works: zero new chrome, no card, no border, no dismiss button. Title + muted sub-line is the universal SaaS "page header" pattern (Linear, GitHub Issues, Notion database views, Vercel dashboards). Eyes skip past it once read, but it's there when needed. Use when: the explanation is one short sentence (≤120 chars) and audience is mixed (everyone benefits from the reminder). Avoid when: the explanation needs links, code, or multiple paragraphs.

Why this fails: amber tone reads as a warning (used elsewhere on the app for "at risk" status) which causes cognitive friction. The brick is ~64px tall — three table rows' worth of vertical space — and it's there every single visit forever. The copy is two sentences which is fine, but the housing is wrong.

Recommendation: A as default + B for complex pages

Use Option A (muted line under title) as the default treatment for every page that currently has the yellow brick. It's the most visually-quiet, zero-chrome SaaS-standard. Most of the existing copy collapses to a single short sentence ("Each card is a photo tagged to one event"), which fits Option A cleanly. For pages with genuinely longer or linked explanations — for example, the Photo tray's evidentiary-only / supplement-rules behaviour — pair Option A with Option B (? icon popover) so the long-form content is one click away. Skip C/D unless a specific page needs them. For empty states across all pages, level up the empty-state message (Option E pattern) so brand-new users get a friendlier paragraph — but that's polish for later.
