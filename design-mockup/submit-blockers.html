Honest take — what modern SaaS actually does in 2026

  • Linear, Figma, GitHub PR merge → all use pattern A or B. Compact indicator with detail-on-demand. Don't shout the error inline in the action row.
  • Stripe Checkout, Vercel deploy → pattern B. Submit button itself says "Add card to continue" / "Resolve 3 errors". The button IS the validator.
  • Notion, Asana → pattern C. Progress meter or checklist gauge that gamifies completion. Works because their forms are long.
  • Airtable, Linear cycle review → pattern D. The existing structure (sections, fields) carries the status — no separate indicator at all.

My recommendation for SiteOps DR

  • Pattern D + bits of A. You already render the 7 section pips in the progress card. Repurpose them: green=done / amber=partial / red=blocker. Eliminate the chip entirely. Add the small "3 items blocking" pill ONLY as a hover-popover on the Submit button (pattern A) so users get the full list with one hover when they're about to click Submit and can't.
  • Why this is cleanest: the header becomes [Back] [spacer] [+ Coord] [Export] [Submit] — zero validation noise unless the user hovers the disabled Submit. The validation lives where it semantically belongs — on the sections themselves (pips) and on the Submit button (hover detail).
  • Bonus: on Submit hover when blocked, the popover lists the blockers AND lets the user click each one to jump-scroll to that section. Closes the loop.
