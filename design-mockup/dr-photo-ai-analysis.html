Why this design

01

Pin = select

Pinning is the whole selection model — tactile, obvious, multi-select with no checkbox clutter. Pinned tiles get an emerald ring and a 1·2·3 order badge so the super always knows the exact set being sent.

02

Two lenses, one set

Safety and QC run off the same pinned photos — no re-selecting. Amber = safety, sky = QC, carried consistently from button → result card so it scans fast in the field.

03

Severity first

Every result leads with a chip — “Clear”, “2 concerns”, “1 critical” — so a super reads the verdict in a glance and only dives into the sentences when it matters.

04

Findings → logged events

The brilliant bit: a finding converts in one tap to a pre-filled safety event or QC issue, already photo-linked and task-linked. The AI read becomes tracked work, not a dead paragraph.

05

Adaptive length

1 photo → ~2 sentences; a full sweep → up to 6. Foreman only writes as much as the evidence warrants, so the panel never bloats.

06

Stays a feed

Reviews stack newest-on-top, so a super can run Safety, then QC, then re-run after a fix — full history in the DR, all attached to the audit trail below.

Market context: OpenSpace / StructionSite capture + index photos but leave the judgment to people; Procore stores photos with no inline AI read. Pinned-set safety/QC review tied to the DR — with findings that auto-open a tracked event — is the differentiator.
